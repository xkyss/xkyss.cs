# 09 - 插件系统开发计划

## 目标

建立可持续的插件生态：

1. 插件可独立项目开发
2. 插件可独立构建与分发
3. 宿主可动态发现与加载插件
4. 插件故障不影响宿主主流程

---

## 范围定义

本计划覆盖：

- 插件契约定义
- 插件加载机制
- 插件开发者文档
- 示例插件与验收标准

不覆盖（后续阶段）：

- 插件市场
- 远程下载与签名验证
- 进程级沙箱

---

## 阶段划分

## P6.1 插件契约与样例（1-2 天）

交付：

1. 插件开发指南（08-plugin-development-guide.md）
2. 插件开发计划（本文件）
3. QuickLaunch 示例插件（独立项目）

验收：

1. 插件项目可单独构建
2. 插件代码可在宿主中通过手动注册方式运行

---

## P6.2 动态加载 MVP（2-3 天）

交付：

1. [x] 新增 IPlugin 契约（或约定式入口标准）
2. [x] PluginLoader（扫描 plugins 目录）
3. [x] 反射加载 + Register 调用
4. [x] 加载日志与失败隔离

验收：

1. [x] 插件 DLL 放入 plugins 目录后，宿主启动自动生效
2. [x] 某插件加载失败时，其他插件仍可继续加载

当前进度：P6.2 MVP 已启动并完成首版实现，后续进入 P6.3。

---

## P6.3 插件清单与版本治理（2 天）

交付：

1. plugin.json 规范
2. HostVersion / MinHostVersion 校验
3. 插件启用/禁用开关（配置持久化）

验收：

1. 不兼容版本插件被拒绝加载并输出原因
2. 用户可禁用单个插件并在重启后生效

---

## P6.4 质量与发布（2 天）

交付：

1. PluginLoader 单元测试
2. 插件加载集成测试
3. 插件开发模板说明
4. 版本化发布文档

验收：

1. CI 包含插件加载测试
2. 文档支持第三方开发者从 0 到 1 完成插件

## 技术决策

1. 插件运行时：先采用进程内加载（AssemblyLoadContext）
2. API 边界：插件只依赖 MewPad.Core
3. UI 能力：通过 ShellContext 注册项接入
4. 安全策略：先记录异常并隔离失败插件，沙箱后置

---

## 风险与应对

1. 风险：NativeAOT 与反射动态加载存在冲突
   应对：开发版优先支持动态加载，AOT 版先限制插件能力或改进程外模型

2. 风险：插件 API 频繁变更导致生态不稳定
   应对：维护核心契约的兼容窗口，增加版本门禁

3. 风险：插件异常拖垮宿主
   应对：加载和调用都做 try/catch 隔离，记录插件维度日志

---

## 里程碑与完成定义

里程碑 M1：示例插件与文档齐备

- 已有文档与示例代码可供插件作者直接开始开发

里程碑 M2：动态加载可用

- 无需改宿主代码，复制 DLL 到 plugins 目录即可生效

里程碑 M3：可治理

- 支持版本约束、启用禁用与清晰错误反馈
